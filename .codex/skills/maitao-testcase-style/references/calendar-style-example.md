# 日历类测试用例参考样式

本文件基于用户自写样例 `+/Users/maitao/Desktop/+日历改造测试用例.xmind` 提炼，用于后续生成“详情页-日历弹窗-全部日历-资源页-埋点”链路类测试用例时快速对齐风格。

## 适用场景
- 活动详情页存在团期、价格横幅、价格说明、选择日期与人数、选择资源、咨询入口等链路。
- 需求中存在较多状态组合，如售卖方式、团期状态、优惠状态、库存状态、登录态、专员/咨询群配置态。
- 既要覆盖前端展示/交互，也要覆盖神策埋点。

## 顶层组织方式

```text
+项目测试用例
  +前端
  +神策埋点
```

- `+前端`：承接页面展示、弹窗交互、跳转链路、按钮行为。
- `+神策埋点`：承接事件触发、事件名、button_name 等埋点结果。
- 不把埋点混写在前端 case 的预期里。

## 推荐模块顺序

```text
+前端
  +产品详情
  +日历弹窗
  +全部日历弹窗
  +选择资源页
+神策埋点
  +活动详情页-ProductDetailClick
  +填写订单页-SelectDateClick
```

- 模块顺序跟随真实浏览/操作路径。
- 若某一页不存在，就直接移除，不保留空节点。

## 命名模板

### 模块命名
- 优先使用真实页面名、弹层名、区域名。
- 示例：`+产品详情`、`+日历弹窗`、`+全部日历弹窗`、`+选择资源页`。

### 用例命名
- 模板 1：`动作 + 页面区域/对象（条件A&条件B&条件C）`
- 模板 2：`模块/弹窗 - 校验点（场景A/场景B）`
- 模板 3：`页面-事件名（按钮/行为名）`，用于埋点。

示例：
- `查看产品详情-价格横幅（未设置即将开售&不存在调价&所有可售场次付款截止时间<=15天）`
- `多线路日历弹窗-团期卡片（预定）`
- `填写订单页-SelectDateClick（价格明细）`

## 步骤写法
- 步骤保持短链路，通常 2~4 步。
- 步骤重点写清：
  - 入口页
  - 前置业务状态
  - 点击/查看/切换动作
  - 目标页面或弹窗
- 不把大段规则写进步骤，规则尽量放进预期。

示例：

```text
1.一级品类亲子游/营地教育多日营，预定产品&按人数售卖，进入活动详情页
2.点击活动详情页的查看全部日期
3.从底部显示选择出行日期与人数弹窗
4.查看选择出行日期与人数弹窗
```

## 预期写法
- 按以下顺序组织：
  - 先写页面元素
  - 再写默认态
  - 再写切换交互
  - 再写异常/边界
- 分支必须展开成可观察结果，不写“按规则显示”。
- 多分支统一使用 `a.` `b.` `c.` `d.`；若分支下还有说明型子项，用 `d-1）` `d-2）` `c-3-a）` 这类写法；不要写 `1.a.`、`1-2a.`、`2.d-1.`。

示例结构：

```text
1.显示元素A/B/C
2.默认态如下：
  a....
  b....
3.切换后如下：
  a....
  b....
4.异常/边界如下：
  a....
  b....
```

## 大 case 写法
- 同一模块内，如果元素、状态、切换逻辑高度关联，优先收成一个大 case。
- 把“场景拆解”放进预期，而不是拆成十几个碎 case。
- 特别适合以下模块：
  - 价格横幅
  - 团期卡片
  - 出行人数/份数/房间数/车型数
  - 已选浮条&底部按钮
  - 房差/车差说明弹层

## 常见业务维度

### 展示结构维度
- 多线路 / 非多线路
- 详情页 / 日历弹窗 / 全部日历弹窗 / 资源页

### 售卖维度
- 预定人数
- 预定份数
- 卡预约

### 团期状态维度
- 售卖中
- 即将售罄
- 已成团
- 未成团
- 可候补
- 已售罄
- 已满额
- 已截止

### 优惠和价格维度
- 调价
- 立减
- 会员
- 拼单
- 非优惠

### 库存和时间维度
- 库存 >= 阈值
- 库存 < 阈值
- 限量
- 不限量
- 不可售
- 距开售时间
- 距结束时间

### 身份和咨询维度
- 未登录 / 已登录
- 已配置专员 / 未配置专员
- 已配置咨询群 / 未配置咨询群

## 咨询和说明类入口
- 对以下入口，默认单独落 case，不只在大 case 里一笔带过：
  - 开售提醒
  - 房差说明
  - 车差说明
  - 价格明细
  - 房间数咨询专员
  - 房间数进群咨询
  - 候补添加专员
  - 候补进群咨询
  - 更多日期咨询专员
  - 更多日期进群咨询

## 埋点写法
- 埋点 case 保持“操作路径 + 事件结果”结构。
- 只写触发动作和事件结果，不补重复 UI 细节。
- 重点校验：
  - 事件名
  - `button_name`
  - 触发入口

示例：

```text
1.任意预定/卡预约产品，点击活动详情页点击购买按钮打开选择日期弹窗
2.弹窗上点击价格明细，记事件SelectDateClick

1.记神策事件SelectDateClick，button_name为：价格明细
```

## 引用写法
- 公共规则允许用 `见用例《xxx》` 引用，避免整段重复。
- 常被引用的内容通常包括：
  - 起售价逻辑
  - 团期卡片显示信息
  - 价格说明弹层
  - 已选浮条与底部价格
- 最终必须补齐引用目标名，避免留空 `《》`。

## 常见问题
- 不要先按“规则校验”“功能汇总”这类抽象名建模块。
- 不要把一个弹窗的每个小状态都拆成独立碎 case。
- 不要只写默认态，不写套餐切换、月份切换、线路切换、关闭重开后的变化。
- 不要只写状态名称，要直接写页面文案或页面结果，如 `仅余N人/份/车/房间`、`余位通知`、`已满员`。
