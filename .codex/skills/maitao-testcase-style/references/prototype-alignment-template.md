# 原型落位模板

适用于需求中包含 Axure 导出页、HTML 原型页、页面截图、交互稿、标注图的场景。  
目标不是直接写 case，而是先完成：

`原型区域 -> 文字规则 -> 用例节点`

的一一对应。

## 使用时机
- 需求里有页面原型、弹窗原型、流程原型。
- 文字描述很多，但不知道应该挂到哪个页面区域。
- 容易写成“逻辑规则汇总”，而不是“页面脑图用例”时。

## 强制顺序
1. 先看原型，不先写 case。
2. 先拆页面区域，不先拆功能逻辑。
3. 先挂文字规则，不先做排列组合。
4. 最后才写用例标题、步骤、预期。

## 自动初始化草稿的使用边界
- 如果是 Axure/HTML 原型页，可以先用脚本自动起一版落位草稿：

```bash
node .codex/skills/maitao-testcase-style/scripts/html_to_prototype_alignment_draft.js --input "requirments/日历改造/产品详情.html" --output "testcases/产品详情-原型落位草稿.md"
```

- 这一步只用于“起草页面区域骨架”，不等于已经完成原型落位。
- 自动稿通常会混入几类内容，必须人工回收：
  - 按钮文案，如 `计算我的出行价格`
  - 展示值，如 `¥5980`、`8人已报名`
  - 状态词，如 `仅余10人`
  - 活动标签或营销文案，如 `50元开卡礼`
- 人工修正时，优先把这些词归并回真实页面区域，例如：
  - `¥5980`、`立减20`、`8人已报名` -> `价格信息区`
  - `计算我的出行价格`、`开售提醒我`、`我知道了` -> `底部按钮`
  - `我要咨询`、`进群咨询` -> `咨询入口`
  - `仅余10人`、`报名中` -> `团期卡片`
- 如果自动稿和原型图上的视觉区块划分冲突，以原型图为准，不以自动抽到的词为准。

## 最小落位表

先按下面格式做一版草稿：

```text
页面/弹层：产品详情页

1. 页面区域：价格横幅
   - 原型位置：页面头部价格区上方
   - 页面动作：查看 / 点击横幅
   - 文字规则：
     - 显示起售价
     - 显示已售N份/N人已报名
     - 设置开售时显示倒计时
   - 后续用例节点：
     - 查看产品详情-价格横幅（条件A）
     - 查看产品详情-价格横幅（条件B）

2. 页面区域：价格说明弹层
   - 原型位置：点击价格横幅或价格信息后弹出
   - 页面动作：点击价格说明入口 / 查看弹层 / 点击底部按钮
   - 文字规则：
     - 显示常规售价
     - 显示优惠项
     - 显示当前起价
     - 显示起价说明
   - 后续用例节点：
     - 查看价格说明弹层（场景A）
     - 查看价格说明弹层底部按钮（场景B）
```

## 页面区域拆法

### 先拆可见区块
- 头部
- 横幅
- 价格区
- 说明弹层
- Tab
- 卡片
- 列表
- 月份栏
- 已选浮条
- 底部按钮
- 咨询入口

### 再拆可交互区块
- 点击入口
- 切换入口
- 展开收起
- 关闭返回
- 跳转按钮

### 最后拆说明型区块
- 价格说明
- 房差说明
- 车差说明
- 金额明细
- 余位提醒

## 文字规则挂载法

### 正确挂法
- 规则写的是哪里显示，就挂到哪里的页面区域下。
- 规则写的是哪里点击，就挂到对应点击入口下。
- 规则写的是哪个弹层里的文案，就挂到该弹层下。
- 同一条规则影响多个区域时，拆开分别挂。

### 错误挂法
- 不要先建 `起价逻辑`、`库存逻辑`、`按钮逻辑` 这类抽象模块。
- 不要把多个页面区域共用的规则先写成总则，再希望 case 自动长出来。
- 不要看到条件判断就直接开始写 case，先确认它在原型图上作用于哪个区域。

## 落位完成后的产物标准
- 每条需求文字都能回答：它作用于页面上的哪里。
- 每个 case 标题都能回答：它是在看哪个区域/点哪个区域。
- 每个预期都能回答：测试执行时应该在页面上的哪里看到结果。

## 日历类示例

```text
页面：产品详情页

1. 页面区域：价格横幅
   - 文字规则：
     - 未设置即将开售且存在调价，显示调价横幅
     - 点击横幅，显示价格说明弹层
   - 用例节点：
     - 查看产品详情-价格横幅（未设置即将开售&存在调价）

2. 页面区域：价格信息栏
   - 文字规则：
     - 未显示横幅时，显示价格信息栏
     - 点击价格信息栏，显示价格说明弹层
   - 用例节点：
     - 查看产品详情-价格信息（未显示横幅）

3. 页面区域：价格说明弹层
   - 文字规则：
     - 显示常规售价/优惠项/当前起价/起价说明
     - 底部按钮根据可售/预售/不可售切换
   - 用例节点：
     - 查看价格说明弹层（组合价）
     - 查看价格说明弹层底部按钮（可售/预售/不可售）
```

## 自检问题
- 我现在写的模块名，是原型图上真实能看到的区域名吗？
- 这条文字规则，到底是显示规则、点击规则，还是弹层规则？
- 这个 case 如果放进脑图，评审的人能立刻知道它对应原型上的哪块区域吗？
- 如果我删掉“逻辑”这种抽象词，标题还能成立吗？

如果上面有任一问题答不上来，说明还没完成原型落位，不应继续写正式用例。
